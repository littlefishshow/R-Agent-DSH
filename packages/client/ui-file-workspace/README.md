# @deepseek-ai/dsh-client-ui-file-workspace

English | [中文](README.zh.md)

The **file workspace** plugin: a VSCode-like file reader/editor that projects the existing dsh Workspace registry in a second way. The sidebar contains an animated Chat / Files segmented switch. Chat mode leaves the original Workspace/session browser visible; Files mode overlays that same region with filesystem trees rooted at the same `WorkspaceView.path` values, while the [ui-layout-workbench](../ui-layout-workbench/README.md) frame replaces the conversation center with the `workbench` reader. Text-selection **modify/ask** sub-windows are backed by real dsh child sessions. File and folder IO ride the [file-workbench Connection RPC channel](../../host/fileworkbench-io/README.md) on **absolute paths**; the browser cannot import the host package, so `src/client/protocol.ts` mirrors that wire contract.

Behavior facts: there is **one shared Workspace list**, not a second file-folder registry. "Add workspace" uses `ctx.workspaces.pickDirectory()` (the Host's native picker) and registers the selected path through `ctx.workspaces.create()`, so the new Workspace appears in both modes. "Remove workspace" calls the normal Workspace delete operation and never deletes its directory. Files mode renders every direct directory and regular file in each Workspace, loading children only when a directory expands. Its title, header action, list inset, row height, typography, folder state, hover, selection, and action affordances follow the conversation Workspace tree. Per-entry operations — new file, new folder, rename, delete, copy, paste — operate on the real filesystem through the backend. Directory contents load only while Files mode is selected. Either New Session entry first selects Chat mode and then runs the original `ctx.workspaces.startSession()` action.

Opening a file adds or activates a compact browser-style tab whose label is the filename without a redundant file icon; tabs preserve each text document's draft, view mode, and freshness version until closed. Markdown keeps the rich renderer, relative local images, editing, and selection actions. Common UTF-8 source/config files, including Python, open as readable monospace source and can switch to editing. PNG, JPEG, WebP, and GIF open as fitted image previews. PDF and other unsupported binary formats remain visible and open a clear unsupported-preview panel rather than being decoded as text. The document stage matches the conversation's 748px content column instead of stretching content across the center, and text views retain the 80%–180% scale controls. Selecting Markdown text immediately paints its highlight and opens a menu — **modify**, **ask**, **explain**, **summarize**. Clicking outside before choosing an action dismisses the menu and its temporary highlight; file-tree action menus follow the same dismissal rule. Ask and modify open a draft window and create no Session until the operator enters a concrete question or edit request and sends it; explain and summarize start immediately with their fixed focused instruction.

The Host owns one stable parent Session for each Workspace-and-Markdown-file pair. Opening a Markdown document caches its exact content, absolute file index, ISO last-modified time, and freshness version. Starting the first selection conversation performs only a metadata freshness check and reuses that cached snapshot instead of reading the Markdown body again. The parent appears in the conversation Workspace tree as `[File] <workspace-relative path>` and records that first complete `<file_context>` in an Agent-driven model-free turn; the Agent therefore advances its own turn counter before a later human prompt. Every selected passage creates an independent child with `parentSession` pointing at that file row, no inherited events, and exactly one fixed `<file_context>` message before its action instruction, selected text, and line-aligned surrounding source. The hidden opening instruction also carries the selection id, source and rendered offsets, action, title, file version, and color as durable source metadata. The Host folds those fields into the `fileWorkbenchSelection` Session projection. After a browser reload, the client scans live Session summaries, reloads each referenced document only after Files mode is selected, and rebuilds a minimized window plus its clickable highlight. Deleting the child removes its summary, projection, window, and highlight. The parent copy makes the file root inspectable in Chat, while zero event inheritance prevents a child request from receiving both parent and child copies. The floating window hides both child opening inputs and uses the operator's first question or modification request as the child title; later follow-ups remain visible. dsh retains the complete parent and child logs and lineage for compaction, reload, the Workspace tree, and native conversation/trajectory projections. While this plugin is active, grouped and flat conversation lists both place each selection child beneath its labeled file parent. Plugin startup removes historical File Workbench roots and children from the Workspace archive set, repairing installations where those rows were previously hidden without changing ordinary archived sessions.

The sub-window follows the main conversation's centered transcript, Markdown response, tabs, and composer language. Its Chat tab renders only Assistant `text` blocks; private reasoning remains available through the native Trajectory tab instead of appearing as answer prose. The Trajectory tab uses `ui-trajectory`'s complete renderer, including overview, search, folding, request details, token usage, timing, tool records, and earlier-history loading. It can be dragged, resized, portaled over the complete application viewport, or minimized into a bottom dock. The selection highlight and child projection remain active through minimize and restore; each painted range has a same-position DOM hit target carrying its highlight id, so clicking the highlighted text reopens its window without coordinate reconstruction. Selection extraction uses one readable-text projection: ordinary DOM text remains literal, while a KaTeX subtree contributes its TeX annotation once as inline or display Markdown. The resulting Markdown is sent to the child and rendered in the selected-text card, avoiding duplicated MathML/visual glyphs. Closing a created window stops its Agent, detaches it from the Workspace, permanently deletes its Session log, then removes the highlight. A **modify** reply is acceptable when it contains exactly one `markdown` or `md` fenced block; surrounding explanation is ignored and never written, while multiple or incomplete replacement blocks are rejected. Accept compares the current draft's source range byte-for-byte with the line-aligned source captured when the window opened. A valid replacement preserves unrelated draft edits, writes to the window's source tab even when another tab is active, then removes the accepted highlight and performs the same Session deletion; a deletion failure leaves a cleanup-only window that can retry close without applying the replacement again. The reader records the exact visible-text offset for highlight restoration, while the visible-selection→source-range mapping ([`markdown-source-map.ts`](src/client/markdown-source-map.ts)) normalizes Markdown to its visible text while preserving source offsets.

The minus button on a minimized dock entry hides only that entry when dock space is scarce. It preserves the child Session, context, and source highlight; clicking the highlighted source text restores the window and makes its dock entry available again. Permanent deletion remains available only from the window header.

## Model Experience

### Selection child prompt

#### What the model sees

When the operator starts the first action for a file, the stable parent records one complete `<file_context>` in a model-free turn. The child begins with no inherited parent events. Its first step contains exactly one child-local `<file_context>` message with absolute `file_index`, ISO last-modified time, freshness version, and content, followed by the action instruction, selected text, and line-aligned surrounding source. Ask and modify require the operator's non-blank question or edit request; the Host rejects a missing instruction before creating either parent or child. The file-workbench pre-step listener delegates to the existing chain, rejects a missing or repeated child file context, then orders current-step runtime context before the file context and selection question. The child request order is system/preset context, current dsh runtime context, the single file context, then the selection question.

#### Token effect

Conditional and data-dependent: each child contributes one complete-file context, its focused question, and any later follow-ups. No later turn can add another file context. Selecting text alone, switching Chat / Files, browsing Workspace files, and editing without starting an action add zero model tokens.

#### KV Cache effect

The ordinary Chat conversation is unchanged. Every selection from one unchanged Workspace-owned document points at the same stable file parent and starts with no inherited events. Byte-identical system/preset context and the child-local file-context message form the same request prefix before each selection-specific question. A file write changes the version and last-modified fields, intentionally changing that suffix for later children. System prompt and ordinary dsh context assembly remain owned by the selected agent preset rather than this plugin.

## Known Limitations and Deferred Work

- **Highlight paint needs the CSS Custom Highlight API** — engines without it fall back to the dock/chip affordance.
- **Adding depends on the Host native picker** — profiles without the `native` directory-picking capability cannot add a Workspace from this surface; existing Workspaces still render as file trees.
- **Copy/paste is copy-into-directory** — a cut/move is a copy then a delete; there is no in-place move across directories.
- **Unbound document state is page-local** — tabs and drafts without a surviving selection child survive Chat / Files mode switches but not a browser reload. Documents referenced by surviving selection children reopen on the first Files-mode visit.
- **Floating geometry resets after reload** — durable selection metadata restores each surviving child as a minimized window with a clickable highlight, but custom position, size, fullscreen state, and active window tab are not persisted.
- **PDF is listed but not rendered** — the current loopback channel has text and raster-image reads, but no bounded PDF byte/stream endpoint or PDF viewer dependency. PDF tabs therefore show an unsupported-preview message.
- **Modify requires an unambiguous source match** — ask, explain, and summarize can continue from the captured visible text when Markdown source mapping fails, while modify reports an error instead of risking a write to the wrong source range.
